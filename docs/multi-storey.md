# 多楼层图纸的切分、识别与建模规格

真实施工图有三种交付形态：一张图纸里只有一层、每层一个文件、一张图纸里几层平面并排。本规格要求三种形态走同一条链路，不靠模板套用，也不要求用户先把图纸拆好——切分由工具自己完成，模型只读「切分结论 + 每层摘要 + 冲突清单」。

## 1. 为什么不能把整张图当一层

单层假设下，几何规则用整图包围盒做分母。一张 30000mm 宽的并排总图里，单层轴线只有 9000mm，按 `min_length_ratio = 0.4` 判定会被当成「太短，不是轴网」全部丢弃；两层共 8 根柱会被算作同一层；`sheet.level` 只有一个值，planner 只能整体回退默认标高，Revit 侧找不到同名标高时会退到「标高最接近」，静默错层。

因此**楼层不是后处理标签，而是切分阶段就必须产出的结构**。

## 2. 切分（`engine/regions.py`）

切分不依赖图框、图层名或块名，只依赖两类证据：

| 证据 | 做法 | 适用 |
| --- | --- | --- |
| 平面标题 | 识别 `1F / 一层 / 首层 / 地下二层 / 屋顶层 / F3`，归一化为 `1F / B2 / RF` | 有标题的正式图纸（绝大多数） |
| 空白带投影 | 沿最宽空白带递归切分，仅当两半都「像平面」才接受 | 无标题、标题不可读、标题被炸成碎片 |

「像平面」的判据：闭合多段线 ≥ 1，或图块 ≥ 2，或长线（≥ 1500mm）≥ 5 且图元 ≥ 6。这条判据用于挡住标题栏、说明、图例被误切成「平面」。

策略选择：

1. 标题 ≥ 2 个：以标题为种子做 Voronoi 最近分配，所有图元归到最近的标题。这条路径专门处理「几层平面共用一个大外框」——空白带会因为外框线而消失，标题仍然可分。
2. 标题 ≤ 1 个：用空白带切分。单张图若无明显空白带，结果就是一个区域，行为与单层版本完全一致。
3. 非平面小块（标题栏、说明、图例、材料表）：按最近原则并入主区域，不单独成层，也不丢进「未知」。

每个区域解析自己的标高注记：`±0.000` → 0、`3.300` → 3300mm、`标高 -5.400` → -5400mm。缺省单位是毫米，所以一个独立出现的短米制数值（`3.300`、`-5.400`）只可能是标高，不可能是 3.3mm 的尺寸，按米制换算；带 `± / ▽ / 标高 / EL` 前缀的一律按标高读。

区域除了 bbox 与标高，还必须持久化**成员索引**（segments / polylines / blocks / texts）。这些索引是回切契约：缺了它，`detect` 拿到的是「有楼层但 0 个构件」的空区域。这是实测踩过的真 bug，不是防御性设计。

## 3. 楼层身份与冲突

楼层用归一化名字标识，不用「第几个区域」。冲突在 detect 阶段落进 `floors[i].conflicts`，同时进 `ambiguous` 与报告待复核清单：

| 冲突码 | 含义 | 处置 |
| --- | --- | --- |
| `level_unassigned` | 区域找不到标题也找不到标高 | 仍参与识别，但该层构件不建，除非用户在 `level_map` 里显式指定 |
| `level_duplicate` | 同名楼层出现在多个区域/多个文件 | 全部保留识别结果，只由一次裁决决定保留哪个；不自动合并 |

`level_duplicate` 故意不在工具里自动消解：两个文件都写「2F」，可能是一层被拆成两张图（应合并），也可能是两个版本（应择一），这是业务判断，不是几何判断。

## 4. 每层独立识别，层间只做竖向对位

- 每层的图元切片重新跑一遍 detector，构件 id 在多楼层时加 `<floor_key>-` 前缀（`1F-C-001`），单楼层保持原 id，既有调用方不受影响。
- 每层单独建图（`id_prefix = F1-`），关系不跨层混淆：层内关系全部在层内闭合，不产生「1F 的梁搭在 2F 的柱上」这类假边。
- 合并图只保留两类跨层关系：`column_stacks_on`（上下层柱按局部坐标配对，容差默认 100mm）与 `grid_continues`（轴网延续）。超过容差生成 `column_misaligned` 异常；某层没有可对位的柱网生成 `level_gap_unverified`。
- 合并后的 `summary.lines` 多楼层时只保留每层一行 headline，避免几百个构件的逐条说明挤爆模型上下文；单楼层保留原有的逐构件说明。

局部坐标：多区域时每层以自身左下角为原点平移，单区域不动。这样并排总图的四层在 Revit 里是叠在一起的，而不是横着排开两万毫米。

## 5. 规划与执行按层分批

- 标高解析顺序：`config.level_map` 与调用方 `level_map` → 图纸标高 → 都缺失则整层 skip 并告警 `E-3002`。
- 楼层不在映射表但有图纸标高：生成 `create_level` 指令（`element_id = LEVEL:<level>`），并入该层首个批次；Revit 侧按名创建，不再「取最近标高」。
- **批次绝不混层**：每批带 `floor` / `level` / `elevation_mm`，一层可以有多批，但一批只有一层。失败回滚半径因此等于一层，不会连带毁掉邻层。
- `levels[].action` 三态：`exists`（映射表已有）/ `create`（按图纸标高新建）/ `skipped`（无标高可用，整层未建）。执行结果与报告按实际动作口径统计，不把 skip 记成 exists。

## 6. 模型侧怎么读

多楼层任务的返回体不要求模型自己数楼层，只要求它读结论：

```json
{
  "floors": [
    {"level": "1F", "elevation_mm": 0, "source_file": "总图.dxf", "region_id": "R1",
     "counts": {"total": 10, "by_type": {"grid": 4, "column": 4, "wall": 1, "beam": 1}},
     "headline": "14 个构件，12 条关系，1 个拓扑异常", "issues": 1,
     "conflicts": []}
  ],
  "graph_summary": {"headline": "4 层，40 个构件，36 条关系，4 个拓扑异常"}
}
```

模型要判断的三件事因此都有结构化依据：**这是几层**（`floors` 长度与 `level`）、**每层是否可信**（`issues` 与 `conflicts`）、**层间是否对得上**（合并图里的 `column_misaligned` / `level_gap_unverified`）。它不需要也不应该从像素里「看图猜楼层」。

## 7. 三条实测结论（四层并排总图，`samples.build_multi_floor_drawing`）

| 观测 | 结果 |
| --- | --- |
| 切分 | R1–R4，level 1F/2F/3F/4F，标高 0/3000/6000/9000mm |
| 识别 | 40 个构件：每层 4 轴网 + 4 柱 + 1 墙 + 1 梁；构件 id 带层前缀 |
| 竖向 | `column_stacks_on` 12 条（3 个层对 × 4 柱），`column_misaligned` 0 |
| 建模 | 4 批（每层一批），4F 因不在默认标高表生成 `create_level`，created 41 = 40 构件 + 1 标高 |
| 校验 | `missing 0`、`offset 0`、`vertical 0`、`auto_ratio 1.0` |

对照：同一份图纸在单层版本下的结果是「1 张图、8 根柱算一层、16 个拓扑异常」，即本规格要消除的失败模式。

## 8. 边界与不做的事

- 不做图纸纠错：标题写错、两层标题同名、比例尺不一致，都只报冲突，不猜。
- 不做跨层传力分析：`column_stacks_on` 只表示「上下层柱在投影上对位」，不代表荷载路径成立。
- 不做 DXF 以外的矢量解析：PDF 图纸集、扫描图不在本链路内（DWG 通过外部转换器先转 DXF）。
- 不按图框切分：图框在施工图里经常缺失、套用、重叠，把它当唯一依据会在真实图纸上失效。
